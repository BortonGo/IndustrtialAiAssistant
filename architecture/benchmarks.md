# Локальные замеры

[К README](../README.md) · [Проверки](testing.md)

Это результаты отдельных проверок на RTX 4050 Laptop 6 ГБ, а не гарантированная скорость на других документах или компьютерах. Для сравнения нужны одинаковые входные данные, настройки, прогрев и состояние кэша; вместе со временем проверяется качество результата.

## Параллельное распознавание — 09.10.2026

Qwen3-VL 8B Q4_K_M, 20 GPU-слоёв, F16, контекст 16384; EmbeddingGemma также загружена. Один набор из 20 уникальных изображений PDF после прогрева, без кэша описаний. Профиль `document-image-v6-stream-guard`, seed 42; сначала два запроса, затем один.

| Запросов одновременно | Время | Выходных токенов | Пик общей VRAM | Ошибок / обрезанных ответов |
|---|---:|---:|---:|---:|
| 1 | 280,8 с | 3654 | 5867 МиБ | 0 / 0 |
| 2 | 207,8 с | 3929 | 5839 МиБ | 0 / 0 |

Время сократилось на 26%, производительность выросла примерно в 1,35 раза. Ответы имели разную длину; общая VRAM включает другие процессы. Замер не устанавливает причин зацикливания модели в прежних экспериментах.

Воспроизведение при закрытом приложении (отдельные порты 8096/8097):

```powershell
./document_tools/.venv/Scripts/python.exe tests/benchmark_image_parallelism.py <файл.pdf> --output build-qtcreator/benchmarks/vision --count 20 --modes 1 2
```

Параметры распознавания сверялись с [рекомендациями Qwen3-VL Instruct](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct#generation-hyperparameters); работа слотов — с [llama.cpp b11429](https://github.com/ggml-org/llama.cpp/blob/b11429/tools/server/README.md).

## OCR — 10.10.2026

На синтетической странице из 12 строк Windows OCR занял **0,35 с**, Qwen3-VL — **27,98 с** без кэша. В OCR-тексте отличалась одна заглавная буква; числа сохранились. Это проверка одной простой страницы. Таблицы, схемы, две колонки, смешанные обозначения и страницы с рисунками направляются модели.

Стенд: `tests/benchmark_ocr_routing.py --output build-qtcreator/benchmarks/ocr --start-local-server --verify-formats`, запускается Python из `document_tools/.venv` при закрытом приложении.

## Размещение модели и KV-кэш

При llama.cpp b11429, 4984 входных и 192 выходных токенах, с загруженной EmbeddingGemma, переход с 20 слоёв/F16 на 24 слоя/Q8 дал около **10 → 14 токенов/с**, время запроса **24,3 → 18,6 с**. Общая VRAM составила около 5,6 ГиБ.

Этот профиль не принят по умолчанию: в проверке релевантности модель ответила на «Спасибо» посторонними сведениями из истории. Один прогон не доказывает, что причиной был KV-кэш. В INI сохранены 20 слоёв/F16; изменение параметров требует повторной проверки скорости и качества.
