# Local Assistant

Настольный ассистент для работы с документами на локальных языковых моделях. Находит сведения в файлах, отвечает с источниками и сохраняет переписку. После подготовки моделей и зависимостей работает без интернета.

Проект в активной разработке. Стек: **C++17 / Qt 5, Python, llama.cpp, PostgreSQL**. Текущие модели — **Qwen3-VL 8B** для ответов и изображений, **EmbeddingGemma 300M** для поиска.

## Возможности

- Отдельные чаты с историей и памятью, потоковый вывод ответов и Markdown.
- Работа с TXT, PDF, DOCX, DOC и изображениями PNG, JPEG, WEBP, BMP.
- Поиск по смыслу, словам и точным обозначениям; просмотр сохранённых источников ответа.
- Распознавание сканов и фотографий, фоновая очередь с паузой и продолжением.
- Сравнение двух редакций документа, просмотр таблиц и экспорт CSV/XLSX.
- Общая библиотека: добавление готовых документов в другой чат без повторной обработки.
- Просмотр размера хранилища и очистка неиспользуемых копий изображений.
- Состояние локальных сервисов и показатели CPU/RAM; в ответах они используются по запросу.

## Запуск

Нужны Windows x64, Python 3.12/3.13 x64, модели и локальные утилиты. Для сборки проверен комплект **Qt 5.7 / MinGW 5.3**; для запуска готовой сборки Qt Creator не требуется.

1. Подготовьте модели, llama.cpp, Poppler, PostgreSQL и окружения Python по [инструкции установки](architecture/setup.md).
2. Проверьте пути и параметры в [local-assistant.ini](local-assistant.ini).
3. Откройте `CMakeLists.txt` в Qt Creator, выберите комплект и соберите приложение. Актуальная сборка — CMake; старый `.pro` не поддерживается полностью.
4. Запустите приложение и дождитесь готовности моделей и БД. Серверы запускаются автоматически; их состояние и журнал доступны снизу слева.

Для `.doc` нужен установленный Word либо LibreOffice. Для распознавания изображений нужен проектор `mmproj`, соответствующий модели. Подготовка офлайн-компьютера и запуск `.exe` вне Qt Creator описаны в [инструкции установки](architecture/setup.md#данные-и-перенос).

## Как пользоваться

| Действие | Где |
|---|---|
| Отправить вопрос / новая строка | Enter / Shift+Enter |
| Прикрепить до четырёх файлов | «+» в поле сообщения |
| Вставить скриншот | Ctrl+V в поле сообщения |
| Загрузить файлы в фоне | «Документы чата» → «Добавить файл» |
| Посмотреть материалы ответа | «Источники» под ответом |
| Сравнить редакции | Выбрать два документа с Ctrl → «Сравнить два документа» |
| Экспортировать таблицу | Выбрать документ → «Таблицы и экспорт» |
| Повторно использовать документ | «В библиотеку», затем в другом чате — «Из библиотеки» |
| Проверить занятое место | «Документы чата» → «Хранилище» |
| Удалить чат | Правая кнопка на чате → «Удалить чат» |

Во время фоновой обработки можно задавать вопросы по уже готовому тексту и переключать чаты. Вложения конкретного сообщения обрабатываются перед ответом на него. По умолчанию размер файла ограничен 100 МиБ.

## Данные и ограничения

Чаты, извлечённые документы, индексы, библиотека и изображения сохраняются в `storage-data/`; путь задаётся через `storage/dataDirectory`. При обновлении приложения сохраняйте эту папку. Исходные PDF/DOCX/TXT целиком не копируются — оригиналы нужно хранить отдельно.

У каждого чата свой контекст. Документы из библиотеки подключаются явно. Удаление чата не удаляет оригиналы файлов и опубликованные версии библиотеки; очистка хранилища удаляет только неиспользуемые управляемые копии изображений.

Распознавание и ответы модели могут содержать ошибки — проверяйте источники. Полный документ может не поместиться в контекст; автоматического разбора такого файла серией запросов пока нет. Для DOC/DOCX номер страницы может быть неизвестен. Черновики сообщений пока не сохраняются после закрытия приложения.
